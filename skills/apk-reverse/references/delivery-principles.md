# 交付原则：最小可执行

> 由 `apk-reverse` 按需引用。**只在要交付代码时读。**

适用于所有逆向交付形态：纯算还原、unidbg 仿真、真机+RPC。

## 0. 定义

**最小可执行 = 能完成目标的最少代码，不是最少功能。**

唯一判定：

> 删掉任意一行，目标还能达成吗？能 → 这行不该在。

## 1. 五个档位

| 档位 | 形态 | 文件数 | 行数 | 什么时候才用 |
|---|---|---|---|---|
| **A. CLI** | 1 个核心类 + 1 个 main | 2 | 200-300 | 验证可行性、几十次调用 |
| **B. 真机 + RPC** | 1 个 Xposed 模块类 + 1 个客户端脚本 | 2 | 约 230 | 有 root 手机、几千条、当天要 |
| **C1. 常驻单实例** | 1 controller + 1 service | 2 | 约 200 | 连续调用 > 50 次（省掉启动开销） |
| **C2. C1 + 实例池** | + 1 个 Pool 类 | 3 | 约 350 | 单实例排队 > 200ms |
| **C3. C2 + 完整能力** | + 设备管理 / 自适应限流 / 健康检查 | 5-6 | 约 900 | 需自动造身份、失败率 > 10% |

**先做 A 或 C1，验证通过再按触发器升级。禁止跳档。**

## 2. 升级触发器

| 现象 | 才允许升到 |
|---|---|
| 连续调用 > 50 次，每次都要等 JVM/py 启动 | C1 |
| 单实例排队明显（> 200ms 等待） | C2 |
| 单身份被限流/封禁，需要轮换 | C2 |
| 需要自动生成新身份 | C3 |
| 失败率 > 10%，需要自适应退避 | C3 |

**没有出现任何一条，就停在当前档位。**

## 3. 禁止事项

| 禁止 | 理由 |
|---|---|
| 探测/基准/调试类代码进交付物 | `probe*`、`bench`、`directCall` 只该在开发期存在 |
| 未被调用的抽象层 | "以后可能扩展" 是最常见的过度工程借口 |
| 为未验证的假设预留配置项 | 配置项越多，用户越不知道该填什么 |
| 实例数 >> 实际并发 | 白占内存和预热时间 |
| 没有需求就上框架（Spring Boot 等） | 几十 MB 的 jar 只为跑几次 |
| 交付物需要读 3 份文档才能跑起来 | 最小可执行必须能一条命令跑 |

## 4. 交付前自检（逐项打勾）

```
□ 探测/基准/调试代码删掉了吗？
□ 每个配置项都被真正读取了吗？（grep 一遍）
□ 每个类都被调用了吗？
□ 实例数 = 实际并发需求吗？
□ 能用一条命令跑起来吗？
□ README 的"最小路径"能在 5 分钟内走完吗？
□ 有没有"暂时用不到但以防万一"的代码？有就删
□ 验证是否做到了 HTTP 200 + 业务码 0 + 数据非空？
```

四项以上答"否" → 还没到最小可执行。

## 5. "最小" ≠ "能跑就行"：三条底线不能省

| 底线 | 说明 |
|---|---|
| **真实请求验证** | 能产出签名 ≠ 服务端接受。验收三层：200 + 业务码 0 + 数据非空 |
| **失败处理** | 例：unidbg 初始化 1/3 成功率且粘性 → 必须重建实例。这不是过度设计，是必需 |
| **README 最小路径** | 一条命令怎么跑、要放哪些文件、预期输出是什么 |

**最小可执行 = 最少代码 + 三条底线。**

## 6. 反例（真实踩过）

| 交付物 | 问题 | 应该是什么 |
|---|---|---|
| unidbg 工程 | 塞了探针 / 基准 / 直调 4 个辅助类 | 只留核心类 + main |
| 常驻服务 | 一上来 12 实例 + 池 + 限流 | 先 C1 单实例验证 |
| 抓取脚本 | 每实例限速 + 全实例并发 = 总量爆炸 | 一个全局令牌桶 |
| 验证方式 | 只验证"能出签名" | 必须验证服务端 200 + 业务码 0 + 数据非空 |
| 交付说明 | 用户不知道怎么开始 | README 第一条就是可复制命令 |

## 7. 与用户确认的时机

| 时机 | 要确认什么 |
|---|---|
| 开工前 | 走哪条路线（纯算/仿真/RPC）、难度、工时 —— 见 SKILL.md §2 |
| 升级档位前 | 为什么需要升，不升会怎样 |
| 成本超预估 2 倍 | 回来重新报工时，不要默默继续 |

## 8. 一句话

> **先做能验证假设的最小版本，验证通过再按触发器升级。
> 任何"以后可能用到"的代码，都不该出现在交付物里。**
